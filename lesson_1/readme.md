## 📦 Переменные

Начнём с базы - что вообще такое переменная?

**Переменная** - это именованная область памяти для хранения данных. Переменные бывают разных типов, но несмотря на это, все они нужны для одного: хранить те или иные значения.

Давайте пройдёмся по всем **основным типам данных**, которые мы будем использовать в этом курсе:

| Тип данных | Память  | Предел значений                        | Описание                                                          |
| ---------- | ------- | -------------------------------------- | ----------------------------------------------------------------- |
| `char`     | 1 байт  | от −128 до 127                         | Один символ                                                       |
| `bool`     | 1 байт  | `true` / `false`, `1` / `0`, `Y` / `N` | Логическое значение                                               |
| `int`      | 4 байта | от −2 147 483 648 до 2 147 483 647     | Целое число без дробной части                                     |
| `float`    | 4 байта | от 1.2×10⁻³⁸ до 3.4×10³⁸               | Число с плавающей точкой (обычно после значения ставится `f`)     |
| `double`   | 8 байт  | от 2.2×10⁻³⁰⁸ до 1.8×10³⁰⁸             | Число с повышенной точностью после плавающей точки                |
| `string`   | -       | -                                      | Строка - массив символов типа `char`; требует `#include <string>` |

## 🔤 Различия `' '` и `" "`

В программировании действует простое правило:

- **Одинарные кавычки ' '** - для одного символа. Например: `'A'`, `'5'`, `'!'`
- **Двойные кавычки " "** - для строки (массива символов). Например: `"Hello"`, `"C++"`

```cpp
char letter = 'A';       // один символ - одинарные кавычки
string word  = "Hello";  // строка - двойные кавычки
```

Если поставить символ в двойные кавычки - это уже не `char`, а `string` из одного символа. Это разные типы, и смешивать их нельзя.

## 🖥️ Как записывать и выводить данные - `cout`, `cin`, литералы

В прошлом уроке мы уже выводили простую фразу в консоль:

```cpp
std::cout << "Hello, I use Linux btw!";
```

Если нужно вывести значение переменной `s` - подставляем её имя вместо строки в кавычках:

```cpp
std::cout << s;
```

В таком случае в консоль выведется значение `s`. А что если нужно вывести и текст, и значение переменной?

Для этого используются дополнительные операторы `<<`:

```cpp
std::cout << "Value: " << s;
```

После всех операций выше (`3 * 2 = 6`, затем `6 / 2 = 12`... - ждём итога из блока выше), консоль выведет:

```
Value: 12
```

Хорошо. А что если нужно самому ввести значение переменной в уже запущенной программе?

Для этого нам понадобится `std::cin`. Давайте перезапишем переменную `s` - то есть присвоим ей новое значение через ввод с клавиатуры:

```cpp
std::cin >> s;
```

Программа остановится и попросит ввести значение. Разберём, что здесь происходит:

|Элемент|Значение|
|---|---|
|`std::`|Квалификатор пространства имён. Указывает компилятору, что мы используем объект из стандартной библиотеки C++.|
|`cin`|Глобальный объект потока ввода. Расшифровывается как **c**onsole **in**put.|
|`>>`|Оператор извлечения. Считывает данные из потока слева и помещает их в переменную справа.|

Итак, мы считываем введённое пользователем значение и помещаем его в переменную `s`.

### 📄 Перенос строки: `std::endl` и `\n`

А если нужно начать вывод с новой строки? Есть два способа.

**Способ 1 - манипулятор потока `std::endl`:**

```cpp
std::cout << "Hello, I use Linux btw!" << std::endl;
std::cout << "You too?";
```

Фраза `You too?` начнётся с новой строки, потому что `std::endl` выполняет перенос. Разберём его:

|Элемент|Значение|
|---|---|
|`std::`|Квалификатор пространства имён.|
|`endl`|Расшифровывается как **end** **l**ine - конец строки.|
|Что делает|Записывает символ `\n` в поток вывода, а затем **сбрасывает буфер** - принудительно отправляет данные в консоль.|

**Способ 2 - escape-последовательность `\n`:**

```cpp
std::cout << "Hello, I use Linux btw! \n";
std::cout << "You too?";
```

После `btw!` стоит `\n` - специальный символ, означающий переход на новую строку. Результат тот же, но `\n` **быстрее**: `std::endl` сначала пишет `\n`, а потом очищает буфер. `\n` просто пишет символ - без лишних операций. При выводе пары строк разница незаметна, но при работе с большими массивами данных `\n` заметно эффективнее.

## 💬 Правильное комментирование кода

Комментирование - это способ добавить в код поясняющий текст, который **полностью игнорируется компилятором**. Оно нужно для:

- документирования логики,
- временного отключения кусков кода при отладке,
- пояснения неочевидных решений - себе в будущем или коллегам.

В C++ есть два способа комментировать код.

**1. Однострочный комментарий** - подходит для одной строки или её части:

```cpp
// Я закомментировал 1-ю строку
int x = 5; // Переменная x с начальным значением 5
```

Комментирование происходит путём вставки `//` перед нужным фрагментом. Всё, что стоит после `//` до конца строки, считается комментарием.

**2. Многострочный комментарий** - подходит для блоков кода:

```cpp
/*
int q = 7;
int w = 9;
int s = 3;
int f = 5;
*/
```

Всё, что находится между `/*` и `*/`, считается комментарием. Можно охватывать сколько угодно строк.

## 🔄 Альтернатива `std::` - `using namespace std`

Как и обещал, показываю альтернативу - как использовать `cout` и `cin` без приставки `std::`.

Вот тот же код из прошлого урока, но уже без `std::`:

```cpp
#include <iostream>

using namespace std;

int main()
{
    cout << "Hello, I use Linux btw!";
    return 0;
}
```

Всё работает - `std::` нигде нет, но код компилируется и запускается. Это стало возможным благодаря строке `using namespace std`. Разберём её:

|Элемент|Значение|
|---|---|
|`using`|Ключевое слово, говорящее компилятору: «используй то, что указано дальше».|
|`namespace`|Пространство имён - способ сгруппировать связанные имена (функции, объекты, классы), чтобы они не конфликтовали друг с другом.|
|`std`|Стандартное пространство имён C++, в котором живут `cout`, `cin`, `endl`, `string` и многое другое.|
|Что делает целиком|Говорит компилятору: «все имена из пространства `std` считай доступными напрямую - без приставки `std::`.»|

---

### ⚠️ Почему лучше **не использовать** `using namespace std` в больших проектах

Несмотря на удобство, у этого подхода есть серьёзный недостаток - **конфликт имён**.

Представьте: вы написали свою функцию с именем `count`. В стандартной библиотеке тоже есть `std::count`. Если написать `using namespace std` - компилятор запутается: какую `count` вы имеете в виду? Это приведёт к ошибке или, что хуже, к незаметному неправильному поведению программы.

```cpp
using namespace std;

int count = 0; // конфликт с std::count - может вызвать ошибку
```

Чем больше проект и чем больше библиотек подключено - тем выше вероятность такого конфликта.

**Вывод:** `using namespace std` удобен для учёбы и небольших программ. В реальных проектах принято писать `std::` явно - это делает код понятнее и безопаснее.
